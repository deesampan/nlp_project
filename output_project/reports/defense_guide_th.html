1. Workflow ทั้งระบบ — แต่ละขั้นใช้เครื่องมืออะไร

สิ่งที่ทีมเข้าใจตอนนี้ (คำถามที่ถามมา)

"data from zomato (messy data) and clean it to be as top3_restaurants_reviews.csv then => using nltk to delete noise … => then use scikit-learn (tf-idf, logistic regression) for giving score to each comment, and then plot to website"

คำตอบ: โครงใหญ่ถูกแล้ว — ข้อมูลรกจาก Zomato → ทำความสะอาด → โมเดล TF-IDF + Logistic Regression ของ scikit-learn → แสดงบนเว็บ แต่มี 3 จุดที่ต้องแก้:

#ที่เข้าใจที่ถูกต้อง
1Zomato → ทำความสะอาด → top3_restaurants_reviews.csv ไฟล์เดียวข้อมูล Zomato ใช้ทำ 2 อย่างแยกกัน: (ก) ข้อมูลเทรน 134,612 รีวิวที่ทำความสะอาดแล้ว (reviews_clean.csv) ใช้สอนโมเดล และ (ข) รีวิวของเว็บ 1,400 รีวิวของ 3 ร้าน (site_reviews.csv — ไฟล์นี้คือ top3_restaurants_reviews.csv เดิม เปลี่ยนชื่อแล้ว) โมเดลไม่เคยเห็นรีวิวของ 3 ร้านนี้ตอนเทรน
2ใช้ NLTK ลบ noiseไม่ได้ใช้ NLTK แล้ว (เคยใช้ในรุ่นก่อน แต่ถูกเอาออก) การลบ noise ใช้: ฝั่งเว็บ — re (regular expression) + unicodedata ซึ่งเป็นโมดูลมาตรฐานของ Python กับกฎ N1–N4 / ฝั่งข้อมูลเทรน — hashlib (หาข้อความซ้ำ), ftfy (ซ่อมตัวอักษรเพี้ยน), re (ลบลิงก์ อีเมล เบอร์โทร), langdetect (เก็บแต่ภาษาอังกฤษ)
3ให้คะแนนแต่ละคอมเมนต์ แล้ว plot ขึ้นเว็บให้คะแนนแต่ละ "อนุประโยค" ไม่ใช่ทั้งคอมเมนต์ และต้อง หาชื่อเมนูก่อน (ใช้ RapidFuzz ช่วยจับคำสะกดผิด) เพราะคอมเมนต์เดียวชมเมนูหนึ่งแต่ติอีกเมนูได้ (คะแนนทั้งคอมเมนต์ไม่ได้แสดงบนเว็บ ใช้แค่เช็กความแม่นกับดาวในรายงาน) ส่วน "plot" คือ แถบสีที่สร้างด้วย HTML/CSS ใน index.html ไม่มีไลบรารีกราฟ

3. โปรเจกต์นี้ AI ทำ หรือเอามาจาก open source?

โค้ดเขียนโดยใช้ AI ช่วย (Claude Code) ภายใต้การกำหนดของทีม ไม่ได้คัดลอกโปรเจกต์ open source มาทั้งก้อน แต่ใช้ไลบรารีสำเร็จรูป (ข้อ 1 "สรุปเครื่องมือ") และชุดข้อมูลสาธารณะจาก Kaggle ตัวโมเดลวิเคราะห์ความรู้สึกเราเทรนเอง

ประโยคนี้ AI สรุปจากหลักฐานด้านล่าง — ทีมควรปรับให้ตรงกับความจริงว่าใครออกแบบ/ตัดสินใจ/ตรวจส่วนไหน

6. วิธีพิสูจน์ว่าเว็บใช้ NLP จริง

หลักการ: แก้ ข้อความ ของรีวิวหนึ่งรีวิว โดยไม่แตะจำนวนดาว แล้วสร้างข้อมูลใหม่ ถ้าตัวเลขของเมนูเปลี่ยน แปลว่าตัวเลขมาจากการอ่านข้อความ ไม่ได้มาจากดาวหรือพิมพ์ใส่ไว้ตายตัว

รีวิวที่ใช้: ร้าน Biriyani Nights รีวิว 4.5 ดาว ท่อน "The dessert that is gulab jamun is mouth watering and tasty af!" → เปลี่ยนเป็น gulab jamun is stale and tasteless!

7. คำถามที่อาจารย์น่าจะถาม พร้อมแนวคำตอบ

แนวคำตอบเหล่านี้ AI ร่าง — ทีมควรซ้อมพูดด้วยคำของตัวเอง ตัวเลขมาจาก results/model_metrics.json, report.md หรือการรันจริง ตัวอย่างประโยคทุกตัวรันกับโค้ดปัจจุบันแล้ว

1. อธิบาย workflow ทั้งหมดใน 30 วินาที
"เราเอาข้อมูลรีวิว Zomato จาก Kaggle มาทำความสะอาด ได้ 134,612 รีวิวที่มีดาวเป็นป้าย ใช้เทรนโมเดล TF-IDF + Logistic Regression ของ scikit-learn แยกรีวิวของ 3 ร้านไว้ทำเว็บ 1,400 รีวิว ตอนสร้างเว็บ เราลบ noise ด้วย regex, หาชื่อเมนูในแต่ละรีวิว, ตัดรีวิวเป็นอนุประโยค, ให้โมเดลอ่านแต่ละอนุประโยค, ให้เมนูได้ผลของอนุประโยคที่มันอยู่ แล้วนับว่าแต่ละเมนูมีคนชอบกี่คน ผลเขียนลง data.js แล้วหน้าเว็บวาดเป็นแถบสี" (ดูข้อ 1)
2. ใช้ NLTK ลบ noise ใช่ไหม?
ไม่ใช่ (รุ่นก่อนเคยใช้ แต่เอาออกแล้ว) การลบ noise ของเว็บใช้ re + unicodedata ที่มากับ Python และกฎ 4 ข้อ N1–N4 src/run_pipeline.py:77-105 ส่วนข้อมูลเทรนใช้ hashlib หาซ้ำ, ftfy ซ่อมตัวอักษร, re ลบลิงก์/อีเมล/เบอร์ และ langdetect เก็บภาษาอังกฤษ ใช้ regex เพราะกฎเราง่ายและอธิบายได้ทีละบรรทัด ไม่ต้องพึ่งไลบรารีใหญ่
3. Noise ในข้อมูลนี้คืออะไร?
ใหญ่ที่สุดคือ รีวิวซ้ำ 89% (1,317,782 → 143,789) เพราะ Zomato ลงร้านเดียวกันหลายหมวด ตามด้วยสแปมที่ซ้ำเกิน 5 ร้าน (3,734), สั้น/ยาวผิดปกติ (2,765), ไม่ใช่ภาษาอังกฤษ (2,671) และไม่มีดาว (7) — เหลือ 134,612 รีวิวที่ไม่พูดถึงเมนูไม่ได้ลบ แต่ไม่นับคะแนนเมนู ทุกขั้นนับไว้ใน cleaning_funnel.csv
4. โมเดลให้คะแนนทั้งคอมเมนต์หรือเปล่า?
ไม่ คะแนนของเมนูมาจากอนุประโยคที่ชื่อเมนูอยู่ เพราะคอมเมนต์เดียวชมเมนูหนึ่งแต่ติอีกเมนูได้ (ตัวอย่าง Kebab / Biryani ในข้อ 5) คะแนนทั้งคอมเมนต์ไม่ได้แสดงบนเว็บ (ใช้แค่เช็กกับดาวในรายงาน) และคะแนนร้านก็รวมจากโหวตของเมนู
5. ทำไมไม่ใช้ ABSA (Aspect-Based Sentiment Analysis)?
ABSA ต้องมีข้อมูลที่คนติดป้ายระดับ "เมนู + ความรู้สึก" ซึ่งไม่มี (มีแต่ดาวระดับรีวิว) และซับซ้อนเกินกว่าจะอธิบายได้ในงานวิชานี้ เราใช้วิธีที่ง่ายกว่าแต่ได้ผลระดับเมนูเหมือนกัน ข้อแลกคือถ้าสองเมนูอยู่ในอนุประโยคเดียวกันจะได้ผลเดียวกัน
6. ทำไมเลือก TF-IDF + Logistic Regression ไม่ใช้ BERT?
ง่าย อธิบายได้ เทรนบน CPU ได้ และน้ำหนักของคำคือคำอธิบาย: คำที่ดันไปทางลบมากสุดคือ worst (+12.99), pathetic, not, bad; ทางบวกคือ awesome (+9.94), best, amazing, delicious ผลบน 26,678 รีวิวทดสอบ: ถูก 82.2%, macro-F1 0.774 ดีกว่า VADER (72.7%, 0.543) และดีกว่าเดาคำตอบที่พบบ่อยสุด (60.5%, 0.251) BERT น่าจะแม่นกว่า แต่หนักกว่า อธิบายยากกว่า และไม่จำเป็นต่อคำถาม "เมนูไหนดี"
7. ป้ายที่ใช้เทรนมาจากไหน? ทำไมต้องตัด 3 ร้านออก?
จากดาวของรีวิว: ≥ 4 = บวก, 3–3.5 = กลาง, < 3 = ลบ src/train_model.py:75-79 (เป็น "weak label" ไม่มีคนติดป้ายเอง) ตัด 1,223 รีวิวของ 3 ร้านบนเว็บออกก่อนเทรน src/train_model.py:201 เพื่อไม่ให้โมเดลเคยเห็นรีวิวพวกนี้พร้อมดาวมาก่อน — ไม่งั้นผลบนเว็บจะดูดีเกินจริง
8. ระบบแม่นแค่ไหน? วัดระดับเมนูหรือยัง?
ระดับรีวิว: ถูก 82.2%; คลาส "กลาง" อ่อนสุด (F1 0.582) เพราะรีวิว 3 ดาวกำกวม บนรีวิวของเว็บ (ที่โมเดลไม่เคยเห็น) ตรงกับดาว 90.1% (1,034 จาก 1,147) src/run_pipeline.py:307-313 ระดับเมนู/อนุประโยคยังไม่ได้วัดตรง ๆ เพราะไม่มีป้ายระดับอนุประโยค — ใช้ดาวเช็กคร่าว ๆ: "ชอบ" ในรีวิว 1 ดาว หรือ "ไม่ชอบ" ในรีวิว 5 ดาว มี 21 จาก 747 ความเห็น ถ้าทำต่อ จะติดป้ายอนุประโยคด้วยมือสัก 200 อัน
9. ทำไมซ่อนชื่อเมนูกับคำว่า "ordered" และใช้เกณฑ์ 0.4?
โมเดลเรียนจากรีวิวทั้งรีวิว บางคำจึงมีความหมายแฝง ("ordered" ไปทางลบ +4.1, but ขึ้นต้นไปทาง neutral +3.78, ชื่อเมนูมี "ชื่อเสียง" ติดมา) และอนุประโยคสั้นกว่าที่โมเดลเรียน จึงให้เลือกข้างเฉพาะตอนมั่นใจ (±0.4) เช็กด้วยดาว: ความผิดชัด ๆ ลดจาก 52 เหลือ 21 แลกกับความเห็นที่เลือกข้างลดเหลือ 554 จาก 747 ข้อควรพูดตรง ๆ: ค่า 0.4 เลือกด้วยการเช็กเดียวกันนี้ ตัวเลขจึงเข้าข้างมัน
10. ทำไมไม่เอาคำว่า not / no ออกเหมือน stopword ทั่วไป?
เพราะ "not good" จะกลายเป็น "good" ทดลองแล้ว: เก็บคำปฏิเสธไว้ดีกว่า +2.1 จุด accuracy (80.0% → 82.2%) และ +2.5 จุด macro-F1 src/train_model.py:190-191 src/train_model.py:236
11. หาเมนูด้วย NER ไหม? "plot" ขึ้นเว็บใช้อะไร?
ไม่ใช้ NER: โมเดล NER สำเร็จรูป (เช่นของ spaCy) ไม่มีประเภท "อาหาร" และเทรนเองต้องมีข้อมูลติดป้ายที่เราไม่มี จึงใช้พจนานุกรมเมนูของร้าน + RapidFuzz src/run_pipeline.py:155-176 ส่วนหน้าเว็บไม่มีไลบรารีกราฟ — แถบชอบ/ไม่ชอบคือ <span> สองสีที่ความกว้างตามจำนวนคน output_project/web/index.html:304-307
12. มีกรณีที่ระบบผิดไหม?
มี ตัวอย่างจริงจากข้อมูล:
  • "Loved the colorful box that the sandwich wrap was packed in." (รีวิว 1 ดาว) → Sandwich และ Wrap ถูกนับว่า ชอบ ทั้งที่ชมกล่อง
  • "We ordered home made dum biriyani and butter chicken." (1 ดาว) → ชอบ เพราะโมเดลเรียนว่า "home" (+2.43) และ "dum" (+1.16) เป็นคำบวก
  • "but the price is like Paradise biriyani." → Biryani ชอบ (การเปรียบเทียบ)
  • "The biryani was not bad." ได้ −0.076 → ไม่เลือกข้าง ทั้งที่ค่อนไปทางชม
  • "lemonade was not upto mark" ที่ BOX8 ไม่ถูกนับ เพราะเมนูร้านเขียน "Masala Lemonade"; emoji ถูกทิ้ง (TF-IDF อ่านแต่คำ); สองเมนูในอนุประโยคเดียวได้ผลเดียวกัน
13. ทำไมไม่ scrape เอง? เลือก 3 ร้านนี้เพราะอะไร?
Scrape ผิดเงื่อนไขของแพลตฟอร์ม ทำซ้ำไม่ได้ และไม่ใช่งาน NLP ชุดข้อมูลสาธารณะให้คนอื่นตรวจซ้ำได้ ส่วน 3 ร้านนี้คือร้านที่มีรีวิวไม่ซ้ำมากที่สุด src/train_model.py:146-151 ลำดับ % ที่ชอบอาหาร (81% > 52% > 38%) ตรงกับคะแนนบน Zomato (4.1 > 3.2 > 2.9) ทั้งที่เราไม่ได้ใช้คะแนนนั้น
14. ทำไมเมนูต้องมีความเห็นขั้นต่ำ? ความเห็น "กลาง" ไปไหน?
กัน "1 จาก 1 = 100%" ขึ้นเป็นเมนูที่ดีที่สุด ต้องมี ≥ 4 ความเห็นที่เลือกข้าง src/run_pipeline.py:31 ส่วนรีวิวที่แค่เอ่ยชื่อเมนูโดยไม่เลือกข้าง ไม่ถูกนับใน %
