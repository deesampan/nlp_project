# Dashboard

Static site. No build step, no framework, no backend.

## Run it

```bash
cd src
../.venv/Scripts/python app.py
```

Then open <http://localhost:8000>.

`app.py` does two things: serves this folder, and runs the model on CSV files you
upload through the page. Uploading needs the server, so use `app.py` — not
`python -m http.server`, which also caches aggressively and will show you the
*previous* run's numbers after a rebuild, silently and with no error.

`serve.py` still exists for serving the page without the upload feature.

## Uploading your own reviews

On the landing page: type a restaurant name, choose a CSV, press Analyse. One
review per row. A header row is fine, and if the file has several columns the one
with the longest text is used. `data/sample_reviews.csv` is a working example.

Uploads are analysed in memory and never saved — refreshing the page forgets them.

**Do not open `index.html` by double-clicking.** The page loads `data/dashboard.json`
via `fetch()`, which browsers block over `file://` under CORS. You get an empty page
with an error panel. It must be served over HTTP.

If you ever do see stale numbers, hard-refresh with `Ctrl` + `F5`.

## Files

| File            | Purpose                                                     |
| --------------- | ----------------------------------------------------------- |
| `index.html`    | Structure — landing view and restaurant detail view          |
| `style.css`     | All styling                                                 |
| `dashboard.js`  | Data loading, rendering, quadrant chart, sorting, modal      |
| `data/dashboard.json` | Generated by `src/build_slice.py` — do not edit by hand |

Chart.js loads from CDN, so the first load needs an internet connection.

## Regenerating the data

```bash
cd src
../.venv/Scripts/python build_slice.py
```

Rewrites `data/dashboard.json`. Refresh the browser to see changes.
